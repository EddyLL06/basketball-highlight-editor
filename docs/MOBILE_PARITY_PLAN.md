# 安卓端补齐计划

> 建立于 2026-10-27。**这份文档取代 `MOBILE_PC_FEATURE_MATRIX.md` 里的「当前状态」**（那份是 2026-08-28 的快照，不再维护）。
>
> 分工：Claude 负责产品规划、界面设计、验收和监控；Codex 负责开发；老大负责决策、真机测试和发版。

## 1. 现状核对（读代码得出，2026-10-27）

**手机端已有**：手动补漏、批量设置片段时长、轨迹与证据叠加、倍速、分别导出与合并导出、按球员筛选和导出、导出取消、分享、球员分组（存和导入）、检查更新、`.bhe` 项目包导入导出。

**手机端缺**（按「找不到对应代码」判断，不是绝对没有；开发前由 Codex 复核）：

| 类别 | 缺口 |
|---|---|
| 稳定与排错 | 视频存进永久存储（缓存被清会丢）、丢了的找回入口、复制诊断信息 / 运行日志 / 反馈入口、友好错误提示 |
| 审核效率 | 审核撤销、球员标签删除与重命名、项目重命名、导出前「还有 N 个片段没标标签」提醒 |
| 标签与名单 | 新建项目时选球员名单（默认分组、勾选谁来了）、分组编辑 |
| 导出与数据 | 比赛数据（命中率估算、每人进球、时间分布）、按标签各合成一个视频、导出历史、进球效果（慢动作） |
| 大功能 | 多段视频项目、手机与电脑项目互通、分析断点续传、算法参数对齐（裁切倍数等） |

**不需要对齐**（平台本来就不同）：键盘快捷键、Windows 一键更新、显卡 / CoreML 加速（手机有 NPU）、项目文件夹与导出目录选择。

## 2. 阶段

| 阶段 | 内容 | 目标 |
|---|---|---|
| **P1 稳定与排错** | F1 视频找回、F2 诊断与反馈、F3 友好错误、F4 审核撤销、F5 球员标签删除重命名、F6 项目重命名 | 用户不再遇到「没反应」，出了问题我们查得到 |
| **P2 审核与导出** | 球员名单（含分组编辑）、比赛数据、按标签合并导出、导出历史、导出前提醒 | 审核和导出体验接近电脑端 |
| **P3 单独立项** | 进球效果、多段视频、手机电脑互通、断点续传 | 每项先确认用户是否真的需要，再投入 |

**P1 先发一个安卓修复包**（`v0.1.12-android.N`，见第 6 节），P1 其余项做完再发下一个。P2、P3 随正式版本。

## 3. 开发流程（每个功能都走一遍）

1. **Claude 出设计稿**（第 5 节是 P1 的设计稿）：入口位置、界面草图、状态、文案（中英）、验收标准。
2. **Codex 开发**：只在本地提交，一个功能一个或几个提交，不推送。
3. **Claude 验收**：读 diff、跑测试、在模拟器里装包看实际界面和截图，逐条对照设计稿和验收标准，把意见写成文件回给 Codex，直到通过。
4. **老大决策**：真机测试、是否推送、是否发版。

**门禁（不满足不合并）**
- `flutter analyze` 无问题，`flutter test` 全过，新增行为有测试，且**测试不依赖本机环境**（`.venv`、真实 Python/FFmpeg、本机偏好）。
- 所有新文案走 `bheText`，中英都有，英文界面不出现中文。
- 界面在 **360dp 和 412dp 宽**、**深色和浅色主题**、**字体放大到 1.3 倍**下不溢出、不遮挡。
- 触摸目标不小于 48dp；破坏性操作（删除、清空）有二次确认；耗时操作有进度和取消。

## 4. 代码约束

- `apps/mobile/lib/mobile_ui.dart` 已有 6400 多行，**新功能放独立文件**（`apps/mobile/lib/features/<功能>/`），对 `mobile_ui.dart` 只做挂接，单个功能不超过约 30 行。
- 数据与状态逻辑放 `mobile_app_state.dart` 或独立的状态文件，界面文件不直接读写文件、不直接调原生。
- 沿用 `BhePalette`、`bheTheme`、`_InlineNotice`、底部弹窗等现有组件，**不引入新的 UI 库，不另起一套样式**。
- 涉及项目数据结构的改动，必须兼容读取旧项目（旧项目缺新字段不崩溃）。

## 5. P1 设计稿

### 通用设计规则

- **配色**：只用 `BhePalette`。主按钮橙色实心，次按钮描边，破坏性操作用 `error` 红；提示条沿用 `_InlineNotice`（左边 2dp 色条）。
- **底部弹窗**：顶部拖拽条，标题 18sp 加粗，内容左右 16dp，按钮高 48dp，圆角与现有弹窗一致。
- **空状态**：一个图标加一句话加一个动作，不留空白。
- **文字**：中文优先，短句，不出现技术词（`muxer`、`ENOENT` 之类只进诊断信息，不进提示）。

### F1 视频找回（已实现，待审）

- 项目引用的视频找不到：页面顶部红色提示条，「视频文件找不到了，请重新选择原视频。」，下方文字按钮「重新选择视频」，点击进入系统选择器；选对了提示消失。
- 视频在但手机打不开：只提示「这个视频无法播放，请重新选择原视频。」，**不带按钮**（重新选同一个文件没有用）。
- 选的视频和项目记录对不上（分辨率、时长、哈希）：提示「所选视频与项目记录不一致，请选择原始视频。」，保留按钮。

### F2 诊断与反馈

- **入口**：右上角「···」菜单新增「反馈与诊断」（放在「检查更新」下面）。分析失败、导出失败的提示条也带一个「反馈」文字按钮，打开同一个弹窗并预填错误信息。
- **弹窗「反馈与诊断」**（底部弹窗，最高占屏幕 85%）：
  1. 一句说明：「遇到问题时，把下面的信息发给我们。已隐藏你的用户名和文件路径。」
  2. 诊断信息预览（等宽小字，可滚动，最多占弹窗高度 45%），内容：App 版本、安卓版本、手机型号、CPU 架构、可用内存和存储、最近 80 行运行日志、当前错误（如果有）。
  3. 主按钮「复制诊断信息」，复制后按钮文字变成「已复制」2 秒；次按钮「在 GitHub 反馈」「发邮件」（链接和电脑端一致，复用已有常量）。
- **运行日志**：App 在 `files/logs/app.log` 记日志，单个 2MB，超过轮换一份；记录启动环境、打开项目时视频是否可用、分析各阶段和失败原因、导出失败（含轨道格式）、未捕获的异常（`FlutterError.onError`、`PlatformDispatcher.onError`、`runZonedGuarded`）。**不记录视频内容、不记录完整路径**（用户名和目录名按电脑端 `diagnostics.dart` 的方式隐藏）。
- **不做**：自动上传、联网收集。

### F3 友好错误提示

- 新增统一的错误转换函数：把 `FileSystemException`、`PlatformException`（`INVALID_ARGUMENT`、`EXPORT_FAILED`、`VideoError` 等）、`ENOSPC`、权限拒绝、解码失败转成人话：
  - 视频文件找不到 → 见 F1；
  - 存储满 → 「手机存储空间不足，请清理后重试。」；
  - 视频格式手机处理不了 → 「这个视频的格式（{格式}）手机无法处理。」；
  - 没有权限 → 「没有读取这个文件的权限，请重新选择。」；
  - 其它未知 → 「出错了：{一句话原因}」。
- 所有转换后的提示都带「反馈」按钮（F2），原始异常只进诊断信息。
- 现有代码里「没人接」的 `await ...initialize()`、`MethodChannel` 调用都要接上。

### F4 审核撤销

- **行为**：撤销最近一次审核操作（保留、排除、设置标签、改备注、改片段范围），最多 20 步，按项目会话保存在内存里，重开项目清空。
- **入口**：每次操作后底部弹出提示条「已排除 · 撤销」（5 秒，带「撤销」按钮）；审核页顶部「···」里加「撤销上一步」，没有可撤销内容时置灰。
- **反馈**：撤销后回到被撤销的那个片段，并显示「已撤销」。
- **不做**：重做、跨会话历史。

### F5 球员标签删除与重命名

- **入口**：现有「球员标签」底部弹窗里，每一行右侧加「⋯」，菜单有「重命名」「删除」。
- **重命名**：弹出输入框，预填当前名字；不允许空、不允许与其他球员重名（提示「已有同名球员」）；确认后所有已标记该球员的片段一起改名。
- **删除**：二次确认对话框「删除「张三」？已标记的 N 个片段会变成未标记。」，按钮「取消」「删除」（删除用红色）；N 为 0 时省掉后半句。
- **与分组的关系**：重命名和删除只影响当前项目，不影响已保存的分组。

### F6 项目重命名

- **入口**：项目页顶部项目名可点击；「···」菜单加「重命名项目」。
- **对话框**：输入框预填当前名，最多 40 个字，去首尾空白，不能为空；确认后立即更新最近项目列表。
- **不做**：改项目文件夹名（只改显示名）。

## 6. 安卓热修复范围（H 系列，先于 P1 发布）

来源：老大真机日志（视频缓存被清）、用户反馈（`Failed to add the track to the muxer`），以及 Codex 对我首版修复的独立审查（2026-10-27）。**首版修复（原样搬移视频、清理目录）被审查否决**，原因见 H1、H2；已撤掉，重做。

| 编号 | 内容 | 要求 |
|---|---|---|
| **H1** | **项目 ID 安全**（审查阻断项，已发布版本里就有） | 导入项目包时，`project_id` 必须匹配 `^[A-Za-z0-9_-]{1,64}$`，否则、或与本机已有项目重名，一律生成本机新 ID。所有用 ID 拼路径的地方（项目 JSON、封面、`videos/<id>`、删除）都校验规范化后的路径仍在目标目录内。电脑端 `bhe_core` 共用的 `project_package.dart` 一起改，iOS 同受益 |
| **H2** | **视频归属与存储**（审查阻断项） | 每个项目只拥有自己的 `videos/<项目ID>/source.<扩展名>`。**只有来源路径在 `getTemporaryDirectory()/file_picker/` 下才移动，其它来源（含其他项目的视频、项目包里的路径提示）一律复制**，源和目标相同则复用。先写入本次操作唯一的暂存文件，播放器初始化和指纹校验通过后再提交，成功后**只删除旧的那一个 `source.*`**，**不再递归清理目录**，失败只清自己的暂存。旧项目：缓存里还在就迁移，已经丢了走找回 |
| **H3** | **视频找回与错误展示** | 项目页、审核页、分析页、导出页都能看到统一的提示（缺文件带「重新选择视频」按钮，打不开只提示）。重新选择：固定发起时的项目身份和操作代次，防止 A→B 串写；进行中禁止重复点击；整个流程 `try/catch`，用户取消不算失败，失败不动原项目；分析中先取消再换。`videoMissing` 切换项目时清除、由当前项目的校验结果设置和清除。审核页换视频后重建播放器 |
| **H4** | **先校验再清空候选** | `startAnalysis` 先校验源视频，再清空候选；校验失败保留原候选、标签和手工审核。现在会把「视频丢了」变成「审核数据也丢了」 |
| **H5** | **导出** | 两条导出路径读取源视频旋转并 `setOrientationHint`（竖拍视频导出后方向不对）；`a1c46a1` 跳过音轨时返回被跳过的轨道，界面提示「导出成功，部分音轨无法保留」 |
| **H6** | **检测区域编辑器的播放器异常** | 捕获初始化和 seek 异常，释放播放器，提示原因并给出重新选择视频或返回 |

**不进热修复，排到 P1 之后**：APK 下载后被清缓存时的重下载恢复、恢复分析时核对任务属于哪个项目、Android 7–9 保存相册的运行时权限、前台服务 6 小时超时处理、通知权限、前台服务后台启动回滚、代理视频的容量清理、封面迁移后补重试、导出从前一个关键帧开始的取舍说明。

**H 系列发布门禁**：Codex 审查报告里列为「必须」的 7 类测试全部有（同机导出再导入、ID 与删除边界、文件提交失败保全、缓存迁移与已丢失旧项目、重绑异步与隔离、故障界面与状态复位、分析检查失败不丢审核）；Claude 在模拟器里验收界面；老大真机用出错的 `IMG_7…` 视频导出、用丢了视频的旧项目走一遍找回。

## 7. 发安卓修复包

- 标签用 `v0.1.12-android.N`，工作流本来就只打安卓包；`BHE_VERSION` 已转成 `0.1.12+android.N`（带 `-` 的写法会被更新检查当成开发版而**悄悄关掉检查更新**，见 `.github/workflows/release-packages.yml`）。
- 本节记录 `v0.1.12-android.1` 的历史测试发布：当时作为预发布，不更新 OSS 上的 `latest.json`，不推给 App 内更新，链接单独发给用户。0.1.13 起的平台补丁通道见 [发布说明](RELEASE.md)，不能将这里的历史限制套用到新机制。
- `versionCode` 用 CI 运行序号，大于手机上现有的 36，可以直接覆盖安装；签名证书不变。
- **发布前必须**：Codex 审完安卓；真机用出错的那个 iPhone 视频导出验证；老大点头。

## 8. 验收环境

- 模拟器：本机已有 `Pixel_8`（arm64、Android 36，带硬件加速）。debug 包没有本地分析库，只能验证审核、导出、项目管理这类界面和逻辑，**分析本身要真机**。
- 测试数据：需要含视频和候选的项目。办法：从真机导出一个 `.bhe` 项目包导入模拟器，或写脚本生成。由 Claude 负责准备。
- 真机：每个阶段结束时由老大在真机上测一轮。
